# Working notes: gap analysis (draft, code-reading pass)

Status: every item below comes from reading the code and the wiki PRDs.
Nothing here has been reproduced at runtime yet. Each item has a "verify" line
that says how to confirm it in the running app before it goes into the report.

Scope of this pass: the post-interview slice (portfolio generation, assessor
override, fit/gap, export) across `api/` and `web/`. The live audio interview
path (Gemini Live, websockets) is out of scope for the revamp, not out of scope
for the risk list.

## Findings

| # | Sev | Type | Finding |
|---|-----|------|---------|
| F1 | P0 | defective implementation | Portfolio, PortfolioSkill, AssessorOverride and FitGapReport are not tenant scoped. `Portfolio.find(params[:id])` is used in export, fitgap, regenerate_fitgap, show_fitgap; `PortfolioSkill.find` in override. Only Session/Vacancy/Assessment include `TenantScoped`. |
| F2 | P0 | missing spec + defect | A skill that was never discussed can be rated. `ai_level = level.to_i.clamp(1,5)` turns a missing level into L1, coverage state is never used to gate the rating, and an empty transcript is still sent to the model. Fit/gap then reports "Gap" instead of "Not assessed". |
| F3 | P1 | defective implementation | Fit/gap contract mismatch between API and web. API sends `expected_level`, `confidence`; web reads `required_level`, `is_override`. Result: "Required" column renders blank for every row, and the override marker never appears. |
| F4 | P1 | defective implementation | Confidence is whatever the LLM returns. PRD defines it from coverage state and probe_count. The UI and fit/gap treat a low-confidence L1 exactly like a high-confidence one. |
| F5 | P1 | defective implementation | One malformed skill in the model output (bad confidence, blank summary) raises in `create!` and fails the whole portfolio, after `destroy_all` and with no transaction. Sidekiq retries re-spend Gemini Pro calls. `destroy_all` also deletes assessor overrides. |
| F6 | P1 | missing spec | No recovery for stuck states. If enqueue fails after commit the portfolio stays `pending`; if a worker dies it stays `generating`. Regenerate only allows `failed`. UI polls forever and says "about 2 minutes". |
| F7 | P1 | defective implementation | Fit/gap page triggers generation on every 404 while polling, so one page view can enqueue many identical jobs (duplicate Gemini calls, unique-index races). |
| F8 | P1 | defective implementation | Override destroys the fit/gap report first, then regenerates async. If the job fails the report is gone. Override also has no visible audit trail (who, when) in the UI. |
| F9 | P1 | missing spec | No consent notice, retention rule or deletion path for candidates whose audio is transcribed and sent to a third-party model (UU PDP). Narrative fields (culture fit, hiring recommendation) are generated by the model from skill comparison only, with no culture data about the candidate. |
| F10 | P2 | defective implementation | Export: PDF generator may raise on characters outside Windows-1252 (the override line itself contains an arrow). UI export has no error handling, so failure is silent. |
| F11 | P2 | defective implementation | UI states: fetch errors swallowed (blank page), failed state hides `generation_error`, fit/gap shows only one of two narratives and shows the count-only fallback under "Culture fit". |
| F12 | P3 | polish | "You Overridden", discovered skill shows `2` instead of `L2`, `parseLevel` falls back to 1 silently, long quotes/labels overflow, header buttons do not wrap on narrow screens. |

## Constraint signals (would escalate on a live project)

- No RSpec specs, no web test runner, no CI. Any change here is unproven by default.
- API needs Ruby 3.3.2, PostgreSQL, Redis and a Gemini key; README says
  `SECRET_KEY_BASE` must match another service (`rakamin-api`) for shared JWTs.
  Local login path needs to be confirmed from `db/seeds.rb`.
- Wiki mentions a Gemini live model name that differs from the README example;
  model names in env samples may be stale.
